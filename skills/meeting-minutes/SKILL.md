# 闭门会纪要

## 规矩

- 录音、转写稿、声纹库**只在本机或用户自己的服务器上处理**，不发给任何外部服务，也不粘贴到外部网页。
- 声纹属于生物识别信息：声纹库只存本地，不提交 git。
- **先核对，后写纪要。** 说话人名字没经用户确认之前，不要输出正式纪要。

## 步骤

1. **要名单。** 问用户这场会有谁发言，最好让他用 `web/seating.html` 摆好座位、导出 JSON。没有名单也能跑，但人数只能估计，核对时要说明这一点。
2. **跑脚本。**
   - 本机：`python scribe/pipeline.py 录音 输出目录 --attendees 座位.json [--voiceprints 声纹库.npz] [--hotwords 热词.txt]`
   - 远程：`SCRIBE_HOST=... SCRIBE_PY='...' bash scribe/run_remote.sh 录音 输出目录 座位.json`
3. **读稿。** 通读 `named_k*.txt` 和 `review_k*.md`。✓ 是声纹自动填的名字；? 要靠上下文判断：谁点了谁的名、谁在做哪部分汇报、谁在接谁的话。
   - 同一个人常被拆成"长段发言"和"短句接话"两类；声纹对上同一个名字时，两类会自动合并。
   - 零碎的"对/行/嗯"会单独聚成一类，归为"多人短句"。
4. **发核对表给用户。** 每一类写清：建议的名字、依据（声纹分数、上下文证据）、把握高低。另外列出没对上名字的类，以及名单里没找到声音的人。然后等用户改正。
5. **写纪要。** 用户确认后，按议题写纪要和待办；人名用用户给的写法；只听得出音、不确定的名字和数字标"（音）"，集中列进"待确认"。
6. **回写声纹库。** 把确认结果写成 `说话人对名.json`（格式见 `examples/mapping.example.json`），然后运行：
   `python scribe/voiceprint.py build <输出>/emb.npz <输出>/labels_kK.npy 说话人对名.json <会议名> 声纹库.npz --lib 声纹库.npz`
7. **改了名单或声纹库，不必重跑识别：** `python scribe/pipeline.py - <输出> --reuse --attendees ... --voiceprints ...`

## 经验

- 收音器放桌子中间。说话声音小的人，让他坐得离收音器近一点。
- 音量和座位距离只能当旁证：房间混响和每个人嗓门的大小，都会让距离和音量对不上。
- 很多设备的"双声道"其实是同一路声音复制了一份，脚本会自动识别，按单声道处理。
